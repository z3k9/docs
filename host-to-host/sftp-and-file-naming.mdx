## Arborescence des dossiers

La Banque crée un dossier dédié à votre organisation sur le serveur SFTP :

```text
/h2h/customers/
└── [customer_folder_name]/       ← vous déposez ici customer_public_key et les fichiers de paiement
    └── Acknowledgements/         ← la plateforme CIB écrit ici les fichiers d'accusé de réception
```

| Dossier | Utilisation |
|---|---|
| **`[customer_folder_name]/`** | Votre dossier client. Déposez-y votre `customer_public_key` (une fois lors de l'intégration, puis à chaque renouvellement), ainsi que chaque fichier de paiement chiffré. La plateforme CIB recherche les nouveaux fichiers dans ce dossier et les en retire une fois traités. |
| **`Acknowledgements/`** | Dossier dans lequel la plateforme CIB écrit un accusé de réception pour chaque fichier traité. Récupérez-les ici pour le rapprochement. |

<Note>
Déposez votre clé publique et vos fichiers de paiement dans le dossier client lui-même, et non dans le sous-dossier `Acknowledgements`. La Banque confirme le chemin exact de votre dossier lors de la création de votre compte.
</Note>

## Nommage des fichiers de paiement

Utilisez un nom de fichier cohérent afin de faciliter le traitement et le rapprochement des fichiers. Le modèle recommandé est le suivant :

```text
[CustomerCode]_[PaymentType]_[YYYYMMDD]_[HHMMSS].xml.pgp
```

Par exemple :

```text
ACMECORP_INTRABANK_20260601_143022.xml.pgp
ACMECORP_INTERBANK_LCY_20260601_143500.xml.pgp
ACMECORP_FOREIGN_20260601_150000.xml.pgp
```

<Info>
La Banque confirme la convention de nommage lors de l'intégration. Si elle impose un modèle différent, utilisez celui-ci.
</Info>

## Nom des fichiers d'accusé de réception

Les accusés de réception portent le nom du fichier auquel ils se rapportent :

```text
ACK_[OriginalFileName]_[Timestamp].xml.pgp
```

Par exemple :

```text
ACK_ACMECORP_INTRABANK_20260601_143022_20260601_144500.xml.pgp
```

Si un fichier est rejeté, l'accusé de réception porte le nom du motif du rejet, ce qui vous permet d'en connaître la cause avant même de l'ouvrir. Par exemple, un fichier envoyé avant le dépôt de votre `customer_public_key` génère un accusé de réception dont le nom contient `missing_public_key`.

## Encodage et taille

| Attribut | Exigence |
|---|---|
| **Encodage des caractères** | UTF-8 |
| **Fins de ligne** | CRLF ou LF. Les deux sont acceptés. CRLF est recommandé pour les systèmes sous Windows. |
| **Transactions par fichier** | Un fichier peut contenir plusieurs blocs `<transaction>` dans un seul élément `<data>` |
| **Taille maximale du fichier et nombre de transactions** | Confirmés par la Banque lors de l'intégration |
