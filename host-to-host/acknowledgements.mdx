Après le traitement de chaque fichier de paiement, la plateforme CIB écrit un accusé de réception XML chiffré dans le dossier `/Acknowledgements/` de votre dossier client. Il indique un statut pour le fichier dans son ensemble, ainsi que pour chacune des transactions qu'il contient.

## Structure

```xml
<AcknowledgementDocument>
  <header>
    <fileid>Référence du fichier de paiement d'origine</fileid>
    <processeddate>Date de traitement du fichier (YYYYMMDD)</processeddate>
    <timestamp>Heure de génération de l'accusé de réception (HHMMSS)</timestamp>
    <status>FILE_ACCEPTED | FILE_REJECTED</status>
  </header>
  <results>
    <transaction>
      <transactionid>Identifiant de transaction d'origine figurant dans le fichier de paiement</transactionid>
      <status>SUCCESS | PENDING | FAILED</status>
      <bankref>Référence interne de la transaction chez First Bank DRC</bankref>
      <errormessage>Description de l'erreur (uniquement si le statut est FAILED)</errormessage>
    </transaction>
    <!-- Un bloc <transaction> par instruction du fichier d'origine -->
  </results>
</AcknowledgementDocument>
```

## Codes de statut

### Niveau fichier

| Statut | Signification | Action à mener |
|---|---|---|
| `FILE_ACCEPTED` | Le fichier a passé avec succès les contrôles de structure et de schéma. Le résultat de chaque transaction figure dans le bloc `<results>`. | Vérifiez le statut de chaque transaction. |
| `FILE_REJECTED` | Le fichier n'a pas passé la validation, par exemple en raison d'un XML mal formé, d'un échec de déchiffrement ou d'une erreur de schéma. **Aucune transaction n'a été traitée.** L'accusé de réception porte le nom du motif de l'échec, par exemple `missing_public_key`. | Corrigez le fichier et soumettez-le de nouveau. Consultez [Erreurs et support](/host-to-host/errors-and-support). |

### Niveau transaction

| Statut | Signification | Action à mener |
|---|---|---|
| `SUCCESS` | La transaction a été traitée et transmise au circuit de paiement. | Aucune. Conservez la `<bankref>` dans vos archives. |
| `PENDING` | La transaction a été acceptée et est en file d'attente, par exemple dans l'attente de l'approbation de change pour un virement international, ou d'une fenêtre de règlement. | Attendez qu'elle soit finalisée. Contactez la Banque si elle reste en attente plus longtemps que prévu. |
| `FAILED` | La transaction n'a pas pu être traitée. `<errormessage>` en indique le motif. | Analysez le problème, puis soumettez de nouveau uniquement cette transaction dans un nouveau fichier. |

## Récupération et rapprochement

<Note>
La Banque n'envoie pas de notification lorsqu'un accusé de réception est disponible. Votre système doit interroger le dossier `/Acknowledgements/` et rapprocher chaque accusé de réception du fichier que vous avez soumis.
</Note>

Les fichiers d'accusé de réception restent dans le dossier pendant une durée confirmée lors de l'intégration. Au-delà, la Banque peut les archiver ou les supprimer : récupérez-les et conservez-les donc sans tarder.
